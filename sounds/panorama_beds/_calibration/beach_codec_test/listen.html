Codec comparison — beach scene, same source, 4 encodings

Each take is ONE PCM file generated by ElevenLabs, then locally re-encoded by ffmpeg into 3 lossy formats. That means the only variable between the four rows within a single take is the CODEC. Same underlying audio. Any difference you hear = cost of that codec.

What each encoding actually is

  • WAV (lossless): The PCM source wrapped in a WAV container. Every sample is preserved exactly. Reference quality. ~4.0 MB per 22s. Plays in all browsers including Safari.
  • MP3 192 kbps (lossy): Psychoacoustic compression. Discards audio data deemed inaudible under normal conditions. ~517 KB per 22s (~8× smaller than WAV). Plays in all browsers.
  • MP3 128 kbps (lossy): Same codec as MP3 192 but more aggressive compression. ~345 KB per 22s. Plays in all browsers. Typically audibly worse than 192 on sparse or quiet content.
  • Opus 128 kbps (lossy): A different lossy codec — typically outperforms MP3 at the same bitrate on ambient content. ~300 KB per 22s. Plays in Chrome and Firefox; may fail to play in Safari <audio> (Safari's Opus support is partial and container-dependent).

Honest framing notes

  • The earlier version of this page labeled files as "48 kHz vs 44.1 kHz" as if sample rate was the variable. It wasn't — sample rate at both values covers the full range of human hearing. The real variable was always lossless vs lossy.
  • Beach is broadband content (lots of wave noise). Codec quality differences are harder to hear on broadband content than on quiet content. The library scene you heard "scratchy" on is a worse case for lossy codecs. This beach test can't tell you how MP3 192 sounds on the library — only how it sounds on beach.
  • To actually settle the library question we'd need a PCM library generation and the same A/B. Flagging that explicitly.
